# Application strategy

## Connect needs to credible contributions

Build two or three convincing links of **Host need → Genuine applicant evidence → Useful contribution → How to say it**. If experience is limited, honestly describe adjacent skills, willingness to learn within boundaries, and needed guidance. Do not turn interest into claimed competence.

| Project | Emphasize only when supported by applicant evidence |
| --- | --- |
| Family/homestay | Reliability, daily-life help, respect for household routines, cultural exchange |
| Hostel | Reception or service, teamwork, communication, handovers |
| Farm | Actual physical/outdoor work, practical skills, following guidance, willingness to learn |
| Community | Collaboration, sustained participation, respect for community priorities |
| Education | Teaching or tutoring, patience, communication, appropriate scope of responsibility |
| Environmental | Relevant practical work, careful execution, maintenance, or records |

Avoid inflated ability, generic praise, copying the listing, and open-ended promises to do anything. Do not promise independent childcare, machinery use, or professional work without appropriate evidence and agreed duties.

## Questions before applying

Resolve requirement conflicts first. If terms are unclear, put one or two decisive questions in the initial message and leave the rest in the report's **To confirm** list. Do not ask questions the host has already answered clearly.

When current availability is unverified, ask about the dates rather than assume a vacancy. If the user has already contacted the host, continue that conversation without repeating an introduction or changing a commitment.

## Message rules

- For a confirmed hard conflict, write an English inquiry asking whether there is flexibility, not an unconditional application. Translate it when the user's language or request calls for a translation.
- Aim for about 140–220 English words by default, unless the user or host prefers another length; a simple project may need less.
- Open with a real, specific listing detail. Explain a relevant contribution, available dates and stay length, then ask a necessary question and end naturally.
- Use only supplied and confirmed names, dates, experience, and promises. For missing essentials, use an explicit `{{placeholder}}` and label the text an incomplete draft.
- Treat a template as a structural starting point. Remove irrelevant lines and rewrite naturally; template text is not evidence of applicant experience.
- Provide a subject and English body plus a faithful translation when needed. A translation must not add credentials or commitments absent from the English.
- Before calling a message ready to send, remove placeholders, mutually exclusive options, and unsupported self-descriptions. Otherwise keep it labeled **Draft**.
- If the user explicitly asks for a fictional test, label invented applicant statements **Simulation only** and never present the draft as ready to send.
