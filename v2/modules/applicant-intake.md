# Applicant intake: downloadable sheet

Read the host link, screenshots, or description first. Identify minimum stay, dates, language, driving, physical demands, pets, smoking, internet, and any special qualifications. Create a sheet only when major applicant details are missing. If main details are known, analyze directly and mark minor gaps **To confirm**.

## Build and deliver the sheet

- Select relevant fields from the blank [applicant profile template](../applicant-profile-template.md). Make an editable `.xlsx` with a clear title, three columns, appropriate widths, wrapped text, and frozen header: **Question | Your answer | Status/help**. Use one solid main color and lighter solid section fills, without gradients or patterns. If workbook creation fails, use UTF-8 CSV; a UTF-8 BOM can improve compatibility with common Windows spreadsheet apps.
- Ask one thing per row, with a brief hint. Put host-specific questions in the final group. Leave unknown answers empty. A known detail may be prefilled with **To verify** in the status column; never save such data in a public reusable template or skill repository.
- Check that the file exists and can be read before sharing a real download link. Ask only the 3–5 most important questions in chat. Optionally ask, “Would you like a more detailed form?” without delaying delivery of the basic form. Explain that the user can download, fill, and upload it or reply directly in chat. If the link fails, immediately show a short chat table; never pretend the file was sent.
- Do not require a completed form. Stop when major information is missing; do not score, recommend, estimate costs, or write an application at this stage.

## Baseline fields

| Group | Fields and hints |
| --- | --- |
| Identity and name | Name or nickname for the message; passport-issuing country or region if relevant, without number |
| Trip | Actual departure city or airport; arrival and departure dates or ranges; length of stay and flexibility |
| Budget | Transport budget with currency, one-way/return and per-person/group basis; local living budget per day or for the stay |
| Communication and experience | Actual language ability; relevant genuine experience, tasks, duration, and independence |
| Task boundaries | Acceptable hours per day and workdays per week; suitable and unsuitable tasks; physical or tool limits |
| Living conditions | Room sharing, accommodation, meals and dietary needs, pets, smoking, and internet as separate questions |
| Goals | Main travel goals and non-negotiable requirements |
| Host-specific | One to five questions arising from actual host requirements, such as driving, minimum stay, credentials, child care, or dates |

The basic sheet contains only decision-relevant fields. If the user wants a detailed version, add optional luggage, transport preferences, skills, previous host contact, and other relevant items from the template. Ask separately about transport and living budgets; room, meals, and sharing; and pets, smoking, and internet so a single answer cannot hide a different restriction.

Never ask for passport numbers, full birth dates, or private home addresses. Mark the issuing country or region optional if irrelevant and explain its purpose when entry or activity rules matter. Do not prefill experience that the user has not supplied.

## When to move to Stage 2

Usually establish the departure point, possible dates and length of stay, language and relevant real experience, and the applicant's position on decisive tasks and living conditions. A missing budget does not prevent all analysis, but it prevents claiming a cost fits that budget. Continue once these main points are known. Stop in Stage 1 only when a missing fact could change the decision. If the user requests only an objective host summary, provide it as requested.
