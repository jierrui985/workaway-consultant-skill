# 申请策略分析

## 从需求到可信贡献

用「房东具体需求 → 用户真实证据 → 可提供的帮助 → 信中表达」连接两到三个最有说服力的理由。没有经验时诚实突出相关能力、愿意学习的范围以及希望获得的指导，不把意愿写成已经具备的技能。

| 项目 | 优先强调的内容（须有用户证据） |
| --- | --- |
| 家庭 | 可靠性、日常生活帮助、尊重家庭习惯、文化交流 |
| 青旅 | 接待或服务经验、团队协作、沟通与交接 |
| 农场 | 具体体力或户外经历、动手能力、遵守指导、学习意愿 |
| 社区 | 合作经历、持续参与、尊重社区目标与自主性 |
| 教育 | 教学或辅导经验、耐心、沟通、适合承担的角色 |
| 环保 | 与项目相关的实践、细致执行、记录或维护能力 |

避免夸张能力、泛泛赞美、复制整段简介和「我愿意做任何事」等无限承诺。不要因项目涉及儿童、机械或专业活动，就替用户承诺独立承担职责。

## 申请前的问题

优先处理阻碍申请的要求冲突；条件尚不明确时，选一到两个决定性问题放入首次申请，其余放在报告待确认清单。不要重复询问房东已明确写出的内容。

没有当前空缺证据时，用询问式语气确认可接待日期。用户已有沟通记录时承接上下文，不重复自我介绍或改变既有承诺。

## 写信规则

- 默认英文正文约 140–220 词；用户或房东指定长度时按其要求，简单项目可以更短。
- 开头点出一条真实且具体的项目细节，接着介绍相关贡献、可用日期与停留时长，最后提出必要问题并自然结束。
- 姓名、日期、经历和承诺仅取自已提供信息；不能补齐的内容保留 `{{占位符}}` 并标为待补全草稿。
- 模板是结构起点，删除不适用句子后自然重写。不要把模板文字当作用户经历。
- 同时给英文标题、英文正文及逐段语义一致的中文翻译，标题也可附中文释义。中文不能增加英文没有的资格或承诺。
- 准备可直接发送的版本时，确认没有占位符、互斥选择或未经证实的自述；有缺口就保留草稿状态。
