# 项目综合评价

## 六项维度：0–10

| 维度 | 权重 | 重点 |
| --- | ---: | --- |
| 地理吸引力 | 15% | 是否符合用户兴趣、旅行季节和生活偏好 |
| 交通成本 | 15% | 门到门成本相对用户预算的适合程度，以及耗时与可达性 |
| 工作内容 | 20% | 兴趣、职责清晰度、工时、培训与休息安排 |
| 住宿价值 | 15% | 食宿覆盖、条件、隐私和用户实际需求 |
| 文化交流价值 | 15% | 有证据的交流机会及用户目标契合度 |
| 用户匹配度 | 20% | 用户匹配分除以 10 |

前五项可用整数或半分。通用锚点：0–2 为严重不适合；3–4 为明显不足；5–6 为基本可接受但有取舍；7–8 为比较适合；9–10 为高度适合且证据充分。每项说明项目事实、用户偏好和主要取舍；便宜或热门不自动得高分。

没有用户预算时交通成本可报告金额，但适合程度暂不评分；没有兴趣资料时，不凭顾问自己的旅游偏好评分。评分包含主观取舍，权重默认如表，用户可明确调整；调整后总权重须为 100%，比较项目使用同一组权重。

全部可评分时：`总分 = Σ(维度分 × 权重)`，权重使用小数形式。最终四舍五入保留一位小数，推荐等级按展示的分数判断，避免展示分数与等级矛盾。

完整报告第一行展示唯一总分，例如 `综合评分：6.0/10｜谨慎考虑`。后文可解释维度分，但不再提供另一组总分、乐观／悲观分、分数区间或上下限。单一分数是基于当前证据的判断，不意味着未知条件已经确认。

| 分数 | 默认推荐等级 |
| --- | --- |
| 8.5–10 | 强烈推荐 |
| 7–小于 8.5 | 推荐 |
| 5–小于 7 | 谨慎考虑 |
| 0–小于 5 | 不推荐 |

## 缺失信息与优先限制

完整未知的维度标为「待确认」，不打零分、满分或任意中间分。只用可评分维度的权重重新归一：`暂定总分 = Σ(已知维度分 × 原权重) / Σ(已知维度原权重)`，最终只展示一个保留一位小数的分数，并在后续说明中写明「暂定，按已知信息计算」。同时注明已知维度的原始权重合计，即信息覆盖率。

用户匹配分按[用户匹配分析](用户匹配分析.md)计算后除以 10；若它也是暂定分，整个总分都应标为暂定，并单独披露匹配信息覆盖率。不能只报告综合维度均有数字，就宣称全部信息已核实。

已知事实足以支持部分判断时，给一个有依据的维度分，将该维度内仍未知的关键条件另列。没有任何可评分证据或用户尚未回答资料表时，不生成完整评分报告，先补齐最低必要资料。不得为了满足开头格式凭空打分，也不得借此反复追问次要缺口。

优先级高于总分的条件：

- 已确认的硬性要求冲突、用户明确不能接受的条件或有依据的严重问题：当前不推荐，说明改变结论需要什么条件。
- 日期空缺、关键工时与食宿、必要活动授权或主要费用等尚未明确：最多为谨慎考虑，列出最关键待确认项。
- 仅在重要条件已核实、没有明显阻碍且匹配证据充分时使用强烈推荐。

最终用一两句话说明「适合谁」「最大优势」「最主要的取舍／待确认条件」。不要把总分当成客观质量认证。
